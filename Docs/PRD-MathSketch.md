# PRD — MathSketch

버전: v0.4 (FR-10 픽셀 수식 모드 추가, 2026-10-16)
작성일: 2026-10-13
참고 프로젝트: `Formula Simplification`(Mathigram) — MathEngine, Canvas 렌더링, SwiftData 영속성 패턴을 응용

## 1. 배경과 비전

`Formula Simplification`은 "그림 → 수식"(Fourier 근사) 방향을 다뤘다. MathSketch는 반대로, **"수식 조각을 쌓아 그림을 만들고, 그 그림 전체를 하나의 순수 기하 수식으로 환원"**하는 것이 핵심이다.

사용자는 점·선·면 같은 기본 기하 요소부터 원, 별, 사인파 같은 복잡한 "수식을 가진 도형 요소"까지 팔레트에서 캔버스로 드래그해 배치하고, 늘이기·회전·비틀기 같은 변형과 색상을 적용한다. 각 요소는 자신의 변형이 반영된 고유 수식을 실시간으로 보여주며, 캔버스에 놓인 모든 요소의 **도형·변형**은 하나의 **합성 수식(composite formula)** 문자열로 합쳐진다. 이 합성 수식을 복사해서 다시 입력하면, 동일한 그림(의 형태)이 한 번에(파싱 즉시) 재구성되어야 한다. 색상은 수학적 환원 대상이 아니라 **꾸미기(장식) 전용**이며, 대신 캔버스에 쓰인 색들은 "팔레트 서명"이라는 별도의 개성 있는 표현으로 묶어 보여준다.

## 2. 목표 / 비목표

**목표**
- G1. 점·선·면 기본 요소를 포함해 23종 내외의 서로 다른 도형·선·기하 곡선을 팔레트로 제공하고, 각 요소는 배치 즉시 자신의 매개변수 수식을 라벨로 보여준다.
- G2. 이동·비균일 늘이기(스케일)·회전·비틀기(전단, shear) 제스처를 지원하고, 제스처가 진행되는 동안(끝난 후가 아니라) 해당 요소의 수식 라벨이 수치적으로 실시간 갱신된다.
- G3. 캔버스에 있는 모든 요소의 **도형 종류 + 변형**을 하나의 순수 기하 문자열(`SketchFormula` DSL, 색상 정보 없음)로 직렬화/역직렬화할 수 있고, 이 문자열을 입력란에 붙여넣으면 즉시 전체 그림의 형태가 재구성된다.
- G4. 색상은 합성 수식에서 완전히 분리된 **꾸미기 전용** 속성이며, 캔버스에 쓰인 색들은 "팔레트 서명(Palette Signature)"으로 모아 개성 있게(감성적 색 이름 + 스와치 띠 + 한 줄 캡션) 보여준다.
- G5. 앱이 종료되었다가 다시 실행되어도 편집 중이던 캔버스(도형·변형·색상 전부)가 그대로 복원된다 (명시적 저장 없이도 유지).
- G6. 완성작은 갤러리에 명시적으로 저장할 수 있고, 썸네일·제목·합성 수식·팔레트 서명과 함께 다시 불러올 수 있다.
- G7. iPhone 16, iPad(13형 또는 11형) 시뮬레이터에서 전 기능이 동작함을 확인한다.

**비목표**
- 임의 코드 실행이나 외부 수식 라이브러리 연동 없음 (자체 Lexer/Parser/Evaluator만 사용).
- 사진에서 윤곽을 추출하는 Vision 기반 변환(참고 프로젝트의 Convert 탭)은 MathSketch의 1차 범위에 포함하지 않는다. 필요해지면 후속 Phase로 분리한다.
- 3D, 애니메이션 타임라인, 협업(iCloud 동기화)은 1차 범위 밖.
- macOS/visionOS 대응은 1차 범위 밖 (iOS/iPadOS만).
- **색상의 수식 환원**은 의도적 비목표다: `SketchFormula` 문자열만으로는 색이 복원되지 않는다(아래 FR-5 주의 참고). 색까지 포함한 완전 복원은 갤러리 저장/로드 경로로만 보장한다.

## 3. 사용자 시나리오

1. **조립**: 사용자가 팔레트에서 "별" 도형을 캔버스로 드래그한다. 배치되는 순간 `star(points: 5, r: 60)`와 같은 공식 라벨이 요소 옆에 나타난다. 두 손가락으로 모서리 핸들을 당겨 비균일하게 늘이면, 라벨의 스케일 계수가 실시간으로 바뀐다.
2. **기본 요소**: 사용자가 팔레트의 "점"을 캔버스에 찍으면 `point(x: 120, y: 80)` 라벨이 나타난다. "면"을 끌어오면 `plane(w: 100, h: 60)`의 채워진 사각 영역이 생기고, 회전시키면 `rotate(15)`가 추가된다. "선"을 그으면 `line(m: 0.5, b: 20)` 형태의 직선 공식이 보인다.
3. **변형**: 사용자가 비틀기 핸들을 드래그해 전단 변형을 적용하면 라벨에 `shear(0.18, 0)` 항이 나타나고, 회전 핸들로 35도 돌리면 `rotate(35)`가 추가된다. 색상 피커에서 주황색을 고르면 요소가 즉시 그 색으로 칠해지지만, 수식 라벨에는 색 토큰이 전혀 추가되지 않는다 — 대신 하단 "팔레트 서명" 띠에 새 스와치가 추가된다.
4. **합성**: 사용자가 원, 사인파, 별 세 요소를 배치한 뒤 하단 "합성 수식" 패널을 보면, 세 요소의 도형·변형만 `+`로 연결된 하나의 순수 기하 `SketchFormula` 문자열이 실시간으로 표시된다. 그 옆(또는 아래) "팔레트 서명" 패널에는 실제 사용된 색 스와치들과 "노을빛 주황 · 심해 남색 · 라임 그린" 같은 한 줄 캡션이 보인다.
5. **재구성**: 사용자가 합성 수식 문자열만 복사해 "수식으로 그리기" 입력창에 붙여넣고 그리기를 누르면, 세 요소가 정확히 같은 위치·크기·회전·형태로 한 번에 그려진다(색은 기본 중립색으로 시작, FR-5 참고).
6. **지속성**: 사용자가 작업 중 앱을 백그라운드로 보내고 기기를 재부팅한 뒤 앱을 다시 열면, 직전에 배치하던 요소들이 색상까지 그대로 캔버스에 있다 (드래프트 저장은 색 포함 전체 상태를 보관하므로).
7. **갤러리**: 사용자가 "저장"을 누르면 팔레트 서명 캡션이 작품 제목 기본값으로 제안된다("노을빛 주황과 심해 남색의 조화" 등). 저장된 작품은 갤러리에 썸네일로 나타나고, 탭하면 상세 화면에서 합성 수식·팔레트 서명과 함께 다시 열거나 삭제할 수 있다.

## 4. 기능 요구사항

### FR-1. 도형 카탈로그 (ShapeKind)
다음 5개 분류, 23종 내외의 매개변수 요소를 제공한다. 각 요소는 로컬 좌표계 기준 매개변수 `t ∈ [0, 2π]` (또는 선형 도형은 `t ∈ [0,1]`)의 `x(t), y(t)` 정의와, 사람이 읽는 수식 표기(예: `x(t)=r·cos t`)를 함께 갖는다. 점·선·면은 팔레트에서 항상 맨 앞 "기본 요소" 섹션에 노출해, 사용자가 점→선→면→복합 도형 순으로 기하학을 익히는 흐름을 지원한다.

- **기본 요소 (점·선·면)**:
  - 점(`point`): 매개변수 없이 좌표 하나만 가진다. 수식 `P = (x₀, y₀)`. 캔버스에는 채워진 작은 원(마커)으로 그린다. `markerRadius`(기본 6pt, scale과 함께 커짐)만 추가로 가짐.
  - 직선(`line`): 기울기-절편 형태 `y = m·x + b`로 정의되는 무한 직선을, 현재 캔버스 경계까지 클리핑해 그린다. 매개변수 `m`(기울기), `b`(y절편).
  - 면(`plane`): 원점 중심의 채워진 직사각형 영역. 수식 표기는 `{(x, y) : |x| ≤ w/2, |y| ≤ h/2}` (너비 `w`, 높이 `h`). 유일하게 **채움(fill)** 렌더링을 쓰는 기본 요소로, 2차원(면적을 가짐)을 점(0차원)·직선(1차원)과 시각적으로 구분한다.
- **직선류(파생 선 요소)**: 선분(`segment`, 두 끝점), 반직선(`ray`), 꺾은선(`polyline`, n개 제어점), 원호(`arc`, 시작각/끝각), 2차 베지어(`quadBezier`), 3차 베지어(`cubicBezier`)
- **기본 폐도형**: 원(`circle`), 타원(`ellipse`), 정다각형(`polygon`, 변의 수 3~12), 별다각형(`star`, 꼭짓점 수 + 내/외 반지름)
- **삼각함수 곡선**: 사인파(`sine`), 코사인파(`cosine`), 리사주 곡선(`lissajous`)
- **극좌표/기하 곡선**: 아르키메데스 나선(`spiral`), 로그 나선(`logSpiral`), 장미 곡선(`rose`, k값), 카디오이드(`cardioid`), 아스트로이드(`astroid`), 사이클로이드류(`epicycloid`/`hypocycloid`, 스피로그래프)

각 ShapeKind은 고유 매개변수(최대 6개 Double)와 렌더 스타일(`point`/`stroke`/`fill` 중 하나)을 가지며, 매개변수 범위를 벗어나면 안전하게 클램프한다(비정상 값으로 NaN 생성 금지).

### FR-2. 요소 변형 (ElementTransform)
요소마다 다음 변형을 독립적으로 가진다: 위치 `translate(tx, ty)`, 비균일 스케일 `scale(sx, sy)` (스케일 범위 0.1~8.0), 회전 `rotate(θ)` (도 단위, -180~180 랩어라운드), 전단(비틀기) `shear(shx, shy)` (-1.0~1.0). 최종 점은 `P' = R(θ)·Sh(shx,shy)·S(sx,sy)·P(t) + T` 순서로 계산한다 (순서는 고정, UI에서 설명).
- 점(`point`)은 로컬 좌표가 원점 하나뿐이므로 `scale`/`rotate`/`shear`가 기하학적으로는 항등 변환이다 (좌표는 바뀌지 않음). 다만 `scale`은 마커 반지름 크기에는 시각적으로 반영한다 — 이 차이는 인스펙터 UI에 짧게 안내한다.

### FR-3. 제스처 입력
- 한 손가락 드래그 → `translate` 갱신.
- 선택된 요소의 모서리 스케일 핸들 드래그 → 해당 축의 `scale` 갱신 (양 모서리 핸들로 sx/sy 독립 조절).
- 회전 핸들 드래그 또는 두 손가락 회전 제스처 → `rotate` 갱신.
- 전용 비틀기 핸들 드래그 → `shear` 갱신.
- 모든 제스처는 `DragGesture`/`RotateGesture`의 `onChanged`마다(제스처 종료를 기다리지 않고) 요소의 수식 라벨 문자열을 갱신한다. 라벨 갱신은 숫자 포맷팅만 하므로 디바운스 없이 매 프레임 반영 가능해야 한다 — 무거운 파싱이 필요한 합성 수식 재생성만 150ms 디바운스한다.

### FR-4. 요소 색상 (ElementColor) — 꾸미기 전용
- `ColorPicker`로 RGB(A) 선택, 내부적으로 `#RRGGBB` 16진 표기와 HSB 성분을 함께 보관.
- 색상은 **렌더링에만** 쓰인다: `fill` 스타일 요소는 채움색, `stroke`/`point` 스타일 요소는 선/마커 색.
- 색상은 `SketchFormula` 문자열(FR-5)에 **절대 직렬화되지 않는다.** 색은 오직 (a) 드래프트/갤러리 영속성(FR-7, FR-8)과 (b) 팔레트 서명(FR-5a)을 통해서만 보존·표현된다.

### FR-5. SketchFormula DSL (합성 수식 — "하나의 순수 기하 수식")
기존 참고 프로젝트의 Lexer(숫자/식별자/`+-*/^`/괄호/쉼표)를 그대로 재사용하고, 다음을 확장한다:
- 함수 호출에 **이름 있는 인자**(`circle(r: 40)`)를 허용.
- 변형 **수정자 체인**을 `·`(가운데점) 또는 `*`로 연결: `shapeCall · scale(sx,sy) · rotate(θ) · shear(shx,shy) · translate(tx,ty)`. (색 토큰은 문법에 존재하지 않는다 — 파서가 `color(...)`를 만나면 하위호환을 위해 무시하고 경고만 남길 수는 있으나, 포맷터는 절대 색을 출력하지 않는다.)
- 요소 여러 개는 `+`로 연결한 한 줄 문자열이 캔버스 전체의 **형태**를 표현하는 **단일 SketchFormula**가 된다. 예:
  `circle(r: 40) · scale(1.2, 0.8) · rotate(35) · shear(0, 0.15) · translate(120, 60) + star(points: 5, r: 60) · rotate(10) · translate(-80, -40) + plane(w: 100, h: 60) · rotate(15) · translate(0, 140) + point(x: 0, y: -140)`
- 파서는 이 문자열을 `[SketchElement]`(색 제외, 또는 기본 중립색 적용)로 역직렬화하고, 포맷터는 `[SketchElement]`에서 색을 제외한 나머지를 위 문법 문자열로 직렬화한다(왕복 변환 보장, 유닛 테스트로 검증).
- 요소 수 상한 200개, 수식 문자열 길이 상한 20,000자.
- "수식으로 그리기" 입력창에 유효한 SketchFormula를 붙여넣고 확정하면, 파싱 성공 시 캔버스 전체가 **그 즉시(디바운스 없이) 1회 렌더**로 교체된다. 이때 모든 요소는 기본 중립색(예: 짙은 회색 `#1C1C1E`) 또는 요소 종류별로 정해진 기본 팔레트 색으로 시작한다. 파싱 실패 시 어떤 토큰/열에서 실패했는지 에러 배너로 표시한다 (참고 프로젝트의 `MathSyntaxError` 패턴 재사용).
- **주의(비목표 재확인)**: 수식만으로는 색이 복원되지 않는다. 색까지 동일하게 복원하려면 갤러리에서 저장된 스케치를 열어야 한다(FR-8, 전체 `SketchElement` JSON에 색 포함 보관).

### FR-5a. 팔레트 서명 (Palette Signature) — 색상의 개성 있는 표현
합성 수식에서 분리된 색상 정보를, 수학적 환원 대신 다음과 같이 **감성적·장식적으로** 표현한다:
- 캔버스의 모든 요소에서 실제 사용된 고유 색상을 **배치 순서(zIndex 오름차순, 중복 제거)**로 모아 `[Color]` 목록을 만든다.
- `PaletteNamer`(신규 유틸)가 각 색을 Lab 색공간 최근접 매칭으로 50여 개의 큐레이션된 한글 감성 색 이름 테이블(예: "노을빛 주황", "심해 남색", "라임 그린", "서리 라벤더" 등)에 매핑한다.
- UI는 이 목록을 **스와치 띠**(작은 원형 색상 칩을 가로로 나열, 각 칩 탭하면 `#hex`와 이름 표시)로 보여주고, 상위 최대 3개 색의 이름을 가운뎃점으로 이어 붙인 **한 줄 캡션**(예: "노을빛 주황 · 심해 남색 · 라임 그린")을 함께 보여준다.
- 이 캡션은 갤러리 저장 시 **제목 기본값**으로 제안된다(사용자가 자유롭게 수정 가능).
- `SavedSketch`(FR-8)에 `paletteHexes: [String]`로 영속화해, 합성 수식과 독립적으로 보관·재표시한다.
- 팔레트 서명은 수식 파서/평가기의 입력이나 출력이 아니다 — 순수하게 표시·제목 제안용 파생 데이터이며, SketchEngine이 아닌 별도의 작은 모듈(`PaletteSignature.swift`)로 분리해 MathEngine/SketchFormula 문법과 결합되지 않게 한다.

### FR-6. 캔버스 & 렌더링
- SwiftUI `Canvas`로 그린다 (참고 프로젝트와 동일하게 커스텀 `Shape` 대신 즉시 모드 렌더링).
- 각 요소는 로컬 매개변수 샘플링(기본 128 샘플, 도형 복잡도에 따라 48~256으로 조정) 후 변형을 적용한 `Path`로 그린다.
- 렌더 스타일 3종을 지원한다: `point`(작은 채움 원), `stroke`(선으로만, 기존 도형 대부분), `fill`(닫힌 영역을 색으로 채움, 현재는 `plane`만 해당하나 추후 다른 폐도형에도 채움 옵션을 켤 수 있도록 설계).
- 선택된 요소는 바운딩 박스와 4개 스케일 핸들 + 1개 회전 핸들 + 1개 비틀기 핸들을 오버레이로 표시한다.

### FR-7. 영속성 — 작업 중 캔버스 (드래프트 자동저장)
- **Core Data** 단일 엔티티(`DraftCanvas`, 사실상 싱글턴 row)에 현재 캔버스의 `[SketchElement]`(색상 포함 전체 상태)를 JSON `Data`로 저장한다.
- 저장 트리거는 **Combine**: 요소 변경(이동/변형/추가/삭제/색상)마다 `PassthroughSubject<Void, Never>`에 신호를 보내고, `.debounce(for: .seconds(0.8), scheduler: DispatchQueue.main)`로 묶어 백그라운드 `NSManagedObjectContext.perform`에서 저장한다. 제스처 중 수식 라벨 갱신(FR-3)과는 별개의 디바운스 큐다.
- 앱 실행 시(`MyApp.swift`의 `init` 또는 최초 `onAppear`) `DraftCanvas`를 조회해 있으면 캔버스를 복원하고, 없으면 빈 캔버스로 시작한다.
- 앱이 강제 종료되어도 마지막 디바운스 저장 시점까지는 복원 가능해야 한다 (시뮬레이터에서 "앱 스와이프 종료 후 재실행" 시나리오로 검증).

### FR-8. 영속성 — 갤러리 (명시적 저장)
- **SwiftData** `@Model` `SavedSketch { title, createdAt, thumbnailData(.externalStorage), formulaText, paletteHexes: [String], elementCount }` — 참고 프로젝트의 `SavedArtwork` 패턴을 그대로 응용. `formulaText`는 색을 제외한 순수 기하 SketchFormula이고, 색까지 포함한 완전 복원이 필요하면 별도로 보관되는 전체 `SketchElement` JSON(색 포함)을 함께 저장한다.
- 갤러리는 `@Query(sort: \SavedSketch.createdAt, order: .reverse)`로 그리드 표시, 상세 화면에서 "캔버스로 열기"(드래프트를 이 작품으로 교체, 색 포함 완전 복원) 또는 삭제.
- 썸네일은 `ImageRenderer`로 캔버스를 PNG화해 저장.

### FR-9. 상태 관리 / 바인딩
- 루트 상태는 `@Observable final class SketchModel`로 관리하고 `.environment`로 주입.
- 요소 리스트, 선택 인덱스, 인스펙터(스케일/회전/비틀기/색상 슬라이더 및 피커)는 `@Bindable` + `Binding`으로 뷰에 연결한다 (참고 프로젝트 `SettingsView`/`DrawView` 패턴).
- Combine은 FR-7의 자동저장 디바운스, "합성 수식 패널" 텍스트 재계산 디바운스(150ms, 요소 변경 시), 그리고 "팔레트 서명" 재계산 디바운스(150ms, 색상 변경 시)에 한정해서 사용한다 — 무분별한 `ObservableObject`/`@Published`로의 회귀는 금지.

### FR-10. 픽셀 수식 모드 (Pixel Formula) — "한 픽셀씩 계산되는 그림" (v0.4 추가)
수학 예술 작품에서 흔히 쓰이는, **픽셀 (m, n)의 색을 직접 정의하는 수식**(예: `rgb(F(H_0(…)), F(H_1(…)), F(H_2(…)))` + `F(x)=…`, `H_v(x,y)=…` 같은 정의 목록)을 붙여넣으면 캔버스 배경으로 렌더링한다. 도형 요소(FR-1~FR-6)는 그 위에 그대로 겹쳐 그려진다.
- **입력 형식**: LaTeX 부분집합. 문서 서두의 영어 설명("For m = 1, …, 2000 and n = 1, …, 1200 …")과 `where`/`and` 같은 연결어는 무시하고, `rgb(`부터 최상위 쉼표 단위로 문장을 나눈다. 지원 문법: 숫자, 한 글자 변수(병치는 곱셈: `us^2 = u·s²`), `+ - * / ^`, `\frac{}{}`, `\sqrt{}`, `|…|`/`\left|…\right|`(절댓값), `\lfloor…\rfloor`(바닥), `\sum_{s=a}^{b}`(정수 범위 포함, 본문은 다음 `+`/`-`까지 한 항), `e^{…}`(지수함수), `\pi`, `\sin \cos \tan \arctan \ln \exp` 등 내장 함수(`\sin^6(…)` 거듭제곱 표기 포함), 사용자 정의 함수 `F(x)`, 아래첨자 매개변수 `H_v(x,y)`, `L_{u,s}(x,y)`. `\mathrm{rgb}`, `\Big(`, `\left(`, `\tfrac`, `\,`, `×`, `−` 같은 조판 기호는 전처리기가 정규화한다. 크기는 서두의 "2000 × 1200" 같은 표기에서 읽고, 없으면 2000×1200.
- **검증**: 정의되지 않은 함수·변수, 인자/아래첨자 개수 불일치, 채널 3개 미만, `rgb` 누락은 열 번호(가능한 경우)와 함께 한국어 오류로 보고한다. 채널 식은 픽셀 좌표 `m, n`과 상수(`e`, `π`)만 참조할 수 있고, 각 정의는 자기 매개변수만 참조할 수 있다.
- **렌더링**: 수식 AST를 Metal Shading Language로 변환해(사용자 함수 → `float` 함수, `\sum` → 루프 헬퍼, 정수 거듭제곱 → 반복 곱, `e^x` → `exp`) 런타임에 컴파일하고(`mathMode = .safe` — `e^{-e^{-1000x}}` 류의 overflow→∞→0 체인이 정확히 유지돼야 함), 64행 밴드 단위로 디스패치해 GPU 워치독을 피한다. 먼저 1/4 해상도 미리보기를 띄운 뒤 전체 해상도로 교체한다(2000×1200, 50항 이중 합 수식이 iPhone/Mac GPU에서 1초 이내). NaN/∞ 픽셀은 0으로, 채널 값은 0…255로 클램프. Metal이 없는 환경에서는 CPU 트리 워킹 평가기로 아주 작은 해상도만 렌더링한다(정확성 기준 구현이자 테스트의 기준값).
- **표시**: 수식 패널 상단에 "픽셀 수식 · 2000 × 1200 · 정의 11개" 상태 줄(컴파일 중/미리보기/완료 시간/오류)과 **LaTeX 원문 전체**(생략 없음)를 접이식으로 보여준다. "픽셀 수식 지우기" 버튼과 전체 지우기, 실행 취소/다시 실행이 모두 배경에도 적용된다(스냅샷은 `{요소, 픽셀 수식}` 쌍).
- **영속성**: 저장되는 것은 **원문 문자열**(+크기, 정의 개수)뿐이며 이미지는 항상 재렌더링한다. 드래프트(Core Data `pixelFormulaJSON`, 옵셔널 속성 추가 → 경량 마이그레이션)와 갤러리(SwiftData `pixelFormulaJSON`)에 모두 보관하고, 썸네일에는 배경이 합성된다. "캔버스로 열기"는 배경까지 복원한다.
- **비목표**: `\int`, 행렬, 조건식(`\begin{cases}`), 복소수, 다문자 식별자(`\mathrm{x}`)는 지원하지 않는다. 색상은 여전히 SketchFormula DSL(FR-5)에 포함되지 않는다 — 픽셀 수식은 DSL과 별개의 "배경 레이어"다.

## 5. 비기능 요구사항

- **성능**: 요소 추가/변형 시 메인 스레드는 포인트 변형(곱셈 수준의 가벼운 연산)만 담당하고, SketchFormula 전체 재파싱/재직렬화처럼 무거운 작업은 `Task.detached(priority: .userInitiated)`로 분리한다 (참고 프로젝트 `DrawModel.render` 패턴).
- **정확성**: MathLexer/Parser/Evaluator 확장부(이름 있는 인자, 수정자 체인)에 대해 Swift Testing으로 왕복 변환(직렬화→파싱→동일 요소 목록, 색 제외) 테스트를 반드시 둔다. 점/직선/면도 다른 ShapeKind과 동일한 왕복 테스트 대상이다. `PaletteNamer`의 최근접 매칭 결정성(같은 입력 색 → 항상 같은 이름)도 테스트한다.
- **접근성**: 모든 팔레트 버튼·핸들에 `accessibilityLabel`/`accessibilityValue`(현재 각도/배율 등 수치 포함)를 부여하고, Dynamic Type을 지원한다. 팔레트 서명 스와치 칩에도 색 이름을 `accessibilityLabel`로 노출한다(색맹 사용자 배려).
- **멀티 디바이스**: iPhone 16과 iPad(세로/가로, 멀티태스킹 분할 화면 최소 대응)에서 레이아웃이 깨지지 않아야 한다 — `TARGETED_DEVICE_FAMILY = "1,2"`.
- **데이터 안전성**: Core Data 드래프트 저장과 SwiftData 갤러리 저장은 서로 다른 스토어이므로, 하나가 손상되어도 다른 하나에 영향이 없어야 한다(독립 컨테이너).
